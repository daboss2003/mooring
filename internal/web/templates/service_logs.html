Retained log search is off. When on, Mooring captures each running service's output (stdout/stderr) into a searchable, time-bounded history — so you can find the error behind an Errors-tab entry without live-tailing. It's opt-in because it writes the app's own output to disk (which may contain secrets the app prints); it's kept in a 0600 file in the data dir on a short TTL and is readable only by a signed-in operator. To enable it, set in /etc/mooring/config.yaml:

server:
  service_log_enabled: true

You can still live-tail the service any time — that never writes to disk.
